# Android customization tools for FlashDock v1.8

Start with a guided **Customize** card next to Connection Check. It should help people find the right Android settings, prepare wallpapers, and preview screen changes through FlashDock’s existing mirroring tool. Put APK inspection in the Sideload & App Manager and keep test tooling in the developer workflow.

## Suggested implementation order

1. **First-run checks and guided settings.** Use Connection Check to explain whether Android is authorized and which tools are available. Offer manufacturer-aware Settings help even when no phone is connected. Cover missing tools, unauthorized ADB, multiple devices, and an unknown handset.
2. **Files and mirroring.** Improve the existing scrcpy experience, then add shared-folder transfer with destination review and overwrite confirmation. Test a disconnected phone and a device switch during review before enabling push.
3. **Optional package and palette previews.** Add SDK-backed APK inspection with separate labels for verified, failed, and unavailable. Try the wallpaper palette as an offline preview with no dependency on a connected phone. Evaluate bundletool once basic inspection is stable.
4. **Compatibility evidence.** Record whether each feature was checked in an emulator or on named physical hardware. Verify vendor-specific Settings instructions before promoting them beyond the general guide.

Keep these features confined to user-selected devices and files. Use normal Android setup and authorization. Tool installation and updates should be explicit, use the publisher’s official source, and show the version and path FlashDock will use.
