# FlashDock v1.8 roadmap

## Goal

Make FlashDock easier to launch on a clean Windows PC, easier to set up with a new phone, and clearer about which operations have been tested. Use v1.8.0 for setup, safety, and release reliability. Deliver the remaining features through v1.8.x.

## v1.8.0 release requirements

- **Connection Check.** Add a read-only workstation page that reuses the device monitor and Tools Manager. Show tool paths and versions, the selected phone, its connection mode, and the next action for missing tools, unauthorized ADB, multiple devices, or a Windows driver warning. Mark the cause as undetermined when FlashDock lacks evidence to identify it.
- **Write Safe and Dry Run.** Audit write-capable entry points, starting with backup and restore calls that pass `dry_run=False`. Check the selected target, connection mode, and write state before dispatch. Dry Run shows the intended operation without invoking a device write. A change of device or mode during review requires a fresh review.
- **Unisoc signing status.** Mark built-in signing unavailable and disable the UI action that depends on the placeholder. Explain the availability in the card.
- **Compatibility matrix.** Record model, Android version, connection mode, feature, FlashDock version, result, and test date. Begin with emulator sideload checks and read-only detection on available physical hardware. Show **Tested**, **Known limitation**, and **Untested** per feature in the app. Keep serials and personal device data out of the published matrix.
- **Windows release verification.** Add GitHub Actions to test the source, build and extract both ZIPs, compare hashes, and check packaged startup on a clean Windows runner. Exercise the developer setup from a path with spaces, and record the results with the release.
- **Trusted Windows signing.** Once a trusted publisher signing service is available, sign the Windows distribution, verify the signature, and launch the downloaded build on clean Windows 11 with Smart App Control enabled. Until signing and launch verification pass, publish a clearly labeled **source-only developer preview**. Hold the stable Windows ZIP for the signed release. [Microsoft Smart App Control guidance](https://support.microsoft.com/en-us/windows/security/threat-malware-protection/smart-app-control-frequently-asked-questions)

## v1.8.x feature backlog

| Order | Feature | What to ship |
| --- | --- | --- |
| 1 | APK inspector | Inspect packages in Write Safe without a connected phone. Show package ID, version, SDK requirements, archive integrity, and signing status. Optionally use Google `apksigner` for verification and `apkanalyzer` for metadata. Label unavailable results. |
| 2 | Verified backups | Show the recorded model, slot, partition list, size, and checksum results. Offer a standalone **Verify Backup** action. Block restores from damaged backups or to a confirmed mismatched target. |
| 3 | Support report preview | Extend the existing local log export with app and tool versions, connection mode, and the last error. Mask serials, local paths, and account identifiers. Preview the report before saving. |
| 4 | Device readout export | Save a read-only snapshot of model, Android version, battery, storage, connection mode, and tool availability. Support before-and-after comparison. |
| 5 | Storage and file transfer | Browse and copy files from shared storage with a destination, size, and progress display. Put copies to the phone behind Write Armed. Confirm overwrites. |
| 6 | Sideload session history | Record package name, version, result, and time locally. Offer a clear-history action. Recheck the target and package before a retry. |
| 7 | Tool versions and updates | Show which ADB, Fastboot, and scrcpy copies FlashDock uses. Use official sources and display the installed and available versions before updating. |
| 8 | Restore checklist and disk space | Show free space, backup integrity, selected device, and pending checks before restore. Reuse the existing checklist. |
| 9 | scrcpy improvements | Add quality and low-bandwidth presets, clearer disconnect messages, and a visible recording destination. |
| 10 | Accessibility and small windows | Add keyboard navigation, visible focus, and accessible names for icon-only controls. Check common window sizes and Windows scaling levels. |
| 11 | Versioned preference export | Move theme, layout, and other UI preferences between PCs. Exclude device records, credentials, and operation history. |
| 12 | Release update notice | Show a newer stable release and link to its notes. Leave installation under the user's control. |
| 13 | Customization guide | From the device readout, offer guides for built-in Android appearance, accessibility, and default-app settings. Link to a trusted launcher as an optional choice. Label instructions by the Android versions and models where they were checked. |
| 14 | Wallpaper and palette preview | Preview user-supplied wallpapers and Material-inspired color palettes on the PC. Export images and color values. Apply wallpapers through the phone's own picker. |
| 15 | Split-package report | Evaluate optional `bundletool` support for inspecting developer APK sets and comparing them with device profiles. Show unsupported or unknown combinations before users reach Install. |

The research notes give each external tool a proposed role and list the limits of its integration. [Android customization tools](ANDROID-CUSTOMIZATION-TOOLS.md)

## Verification checklist

- Test Connection Check with no device, missing tools, an unauthorized device, multiple phones, and disconnects. Verify stale status cannot be applied to a newly selected phone.
- Exercise Write Safe and Dry Run through real UI entry points with mocked command runners. Fail the tests if a device-write command is dispatched while blocked. Cover target and mode changes during install review.
- Use Android Emulator snapshots and a test APK controlled by the project for install, update, invalid-package, and disconnect cases. Keep physical USB, driver, and Fastboot results separate in the compatibility matrix. [Android Emulator snapshots](https://developer.android.com/studio/run/emulator-snapshots)
- Check both ZIPs and checksums on the build runner. Use a fresh Windows profile, Sandbox, or VM to exercise startup and missing-tool recovery. Before the stable Windows release, additionally verify the signed download on Windows 11 with Smart App Control enabled. [Windows Sandbox](https://learn.microsoft.com/en-us/windows/security/threat-protection/windows-sandbox/windows-sandbox-overview)
- Preserve the existing v1.7.4 downloads and their checksums. Keep nightly results distinct from compatibility results for a published version.
